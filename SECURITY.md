# Security policy

Please do not report an unpatched vulnerability in a public issue or include sensitive documents in a public report.

## Reporting a vulnerability

The public repository is [dukeofwest/universal-file-preview](https://github.com/dukeofwest/universal-file-preview). To report a vulnerability privately, use [GitHub's security advisory reporting page](https://github.com/dukeofwest/universal-file-preview/security/advisories/new). If GitHub does not offer a private report form, do not post vulnerability details publicly; contact the repository maintainer through a private channel and ask for a secure reporting route. Do not include private documents in a report; a small file that reproduces the problem is enough.

Please include the affected package version, the browser, and the steps or file that reproduce the problem.

## What to expect

This is a small, independently maintained project. The maintainer aims to:

- acknowledge a report within 5 business days;
- give an initial assessment (confirmed or not, and its severity) within 10 business days;
- release a fix for a confirmed high or critical issue within 30 days of confirming it, and fix lower-severity issues in a later release;
- publish a GitHub security advisory for each fixed vulnerability, with credit to the reporter unless they prefer otherwise.

These are targets, not guarantees. Please keep the details private until a fix is released or 90 days have passed, whichever comes first, unless agreed otherwise.

## Supported versions

Security fixes are prepared for the latest release; older releases are not guaranteed to receive backports. The project is in early development (0.x), so upgrade to the latest version to receive fixes.

| Version | Supported |
|---|---|
| Latest 0.x release | Yes |
| Older releases | No |

See [the security documentation](./docs/security.md) for the current security boundaries, file-processing limits, and deployment guidance.
